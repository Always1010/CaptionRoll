# 问题日志

## CR-001：文字稿加载会干扰 YouTube 字幕开关

- 日期：2026-09-12
- 状态：已解决
- 现象或修改背景：CaptionRoll 需要用户手动打开播放器字幕后才能稳定显示文字稿，并可能改变用户原有的字幕开关或字幕轨道设置。
- 原因分析：页面钩子为了诱发 timed-text 请求，主动调用了播放器内部的 captions `setOption` 和 `reload`，使文字稿加载与播放器 CC 状态耦合。
- 解决方案：直接使用播放器响应中英文轨道的 `baseUrl` 加载文字稿，保留对用户自然产生的 timed-text 请求的捕获作为备用，但不再写入播放器字幕选项。
- 验证方式：回归测试确认页面钩子不再调用 captions `setOption/loadModule`；真实 Edge 全新配置中未手动打开 CC，扩展直接读取到英文轨道并显示 4 条字幕。
- 相关文件：`page-hook.js`、`tests/page-hook.test.js`

## CR-002：深色主题下中文输入框文字不可见

- 日期：2026-09-12
- 状态：已解决
- 现象或修改背景：收藏夹的中文输入框显示为白色背景和白色文字，无法辨认已经输入或生成的中文。
- 原因分析：输入框继承了面板的深色主题文字颜色，但背景所用的 YouTube CSS 变量在当前页面仍解析为白色。
- 解决方案：为输入框明确设置高对比度的浅色配色，并同时根据系统深色主题和 YouTube 的 `html[dark]` 状态应用深色配色。
- 验证方式：运行 JavaScript 语法与回归测试，并在真实 Edge 深色模式中读取输入框的计算样式，确认文字与背景具备清晰对比度。
- 相关文件：`content.js`、`tests/edge-smoke.mjs`

## CR-004：完整句子会在语义未结束时断开或跨越句号

- 日期：2026-09-12
- 状态：已解决
- 现象或修改背景：较长的口语句会在单词中间位置被拆成多条，同时以 `podcast.`、`test.` 等结尾的句子可能与下一句错误合并，出现半句话在上、半句话在下的情况。
- 原因分析：句子合并逻辑把 34 词和 15 秒作为立即切分的硬上限；缩写保护规则又缺少单词边界，使所有以 `st.` 结尾的普通单词都被误判为 `St.` 缩写。
- 解决方案：为缩写匹配增加词边界；把原有长度限制改为软阈值，并增加更宽松的安全与紧急上限；停顿和安全上限切分前检查两侧词语，避免在冠词、介词、连词及填充词附近断句。
- 验证方式：回归测试覆盖截图中的长口语句、`podcast.` 和 `test.` 句尾、`Dr.` 真正缩写、停顿分句、无标点字幕的安全回退以及原有滚动字幕合并场景。
- 相关文件：`sentence-engine.js`、`tests/sentence-engine.test.js`

## CR-003：字幕已显示后状态仍可能提示等待

- 日期：2026-09-12
- 状态：已解决
- 现象或修改背景：真实 Edge 冒烟测试中已经读取并显示字幕，但面板标题偶尔仍显示“正在等待有效英文轨道”。
- 原因分析：并发的字幕请求中，较晚返回的空响应会在另一请求成功交付字幕后再次写入等待状态。
- 解决方案：只有在空响应返回且尚未交付任何有效字幕时才发布等待状态。
- 验证方式：页面钩子回归测试检查等待状态的双重条件，并重新运行真实 Edge 字幕加载测试。
- 相关文件：`page-hook.js`、`tests/page-hook.test.js`
